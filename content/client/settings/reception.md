## 1. Module Summary
- The Reception Kiosk Settings tab allows practice administrators to configure physical clinic stations (Doctor consultation rooms, Labs, Pharmacy, Billing counters), set queue token prefixes (D-, P-, L-, B-, R-), and define arrival buffers for kiosk check-in.
- Documented directly from MantraAssist figma codebase specifications (src/app/pages, components, and hooks).
- Supports real-time clinical workflows, automated logging, and seamless cross-product synchronization.

## 2. Feature Requests

### F-1: Physical Stations & Consultation Rooms CRUD
#### 1. What it does
Provides an administrative interface to create, edit, and delete physical stations within the clinic: Station Name, Station Type (doctor_room, lab, billing, pharmacy, reception_desk), Room Number, Assigned Clinician, and Active Toggle.

#### 2. What it includes
| Item | Type | What it does | Notes |
| :--- | :--- | :--- | :--- |
| F-1.1: Station List Table | Data Table | Displays all configured stations with type badges, room numbers, and assigned providers | Editable inline or via modal |
| F-1.2: Add/Edit Station Modal | Modal | Captures Station Name, Type dropdown, Room Number, Provider Name, and Active switch | Persists to localStorage and DB |
| F-1.3: Delete Station Confirmation | Dialog | Confirms station deletion with validation that no active appointments are currently routed there | Protects active visits |

#### 3. Worked example
| # | Situation | What the user does | Result |
| :--- | :--- | :--- | :--- |
| 1 | Admin adds new Diagnostic Lab station | Enters 'Phlebotomy Room', type 'lab', room '104' | **Station appears in wayfinding directory and kiosk directions immediately** |

#### 4. Jobs to be done
| # | User | Job to be done |
| :--- | :--- | :--- |
| F-1-J1 | Clinic Manager | When setting up clinic rooms, I want to register our physical stations, so that the AI Receptionist kiosk routes patients to the correct doors. |

#### 5. Acceptance criteria
| # | Criteria |
| :--- | :--- |
| F-1-1 | Given an active station, it appears as an available destination in AI Receptionist directions and check-in routing. |

### F-2: Queue Token Prefix Taxonomy & Timing Buffers
#### 1. What it does
Configures token prefix characters for each station type (Doctor: D-, Pharmacy: P-, Lab: L-, Billing: B-, Reception Desk: R-) and sets kiosk arrival buffers: Early arrival buffer (30m), Late arrival grace window (15m), and Queue aging cap (45m).

#### 2. What it includes
| Item | Type | What it does | Notes |
| :--- | :--- | :--- | :--- |
| F-2.1: Token Prefix Inputs | Text Inputs | Configures 1-2 character prefix for Doctor, Pharmacy, Lab, Billing, and Desk tokens | Defaults to D-, P-, L-, B-, R- |
| F-2.2: Early Arrival Buffer Min | Number Input | Minutes before appointment patient is permitted to check in at kiosk (default: 30m) | Prevents premature queue congestion |
| F-2.3: Late Arrival Grace Min | Number Input | Minutes after appointment time patient can still check in without staff override (default: 15m) | Routes tardy visits to front desk |

#### 3. Worked example
| # | Situation | What the user does | Result |
| :--- | :--- | :--- | :--- |
| 1 | Patient arrives 20 minutes before 10:00 AM visit | Kiosk permits check-in because 20m < 30m early buffer | **Kiosk issues ticket 'D-102' and updates appointment to Arrived** |
| 2 | Patient arrives 45 minutes late | Kiosk flags arrival exceeds 15m grace window | **Aria prompts patient: 'Your appointment was scheduled for 10:00 AM. Please speak with the front desk coordinator.'** |

#### 4. Jobs to be done
| # | User | Job to be done |
| :--- | :--- | :--- |
| F-2-J1 | Practice Manager | When managing patient queue flow, I want arrival buffers enforced, so that late arrivals do not disrupt the scheduled doctor timeline. |

#### 5. Acceptance criteria
| # | Criteria |
| :--- | :--- |
| F-2-1 | Patients arriving past the late arrival window are directed to front desk staff rather than issued an automated token. |
